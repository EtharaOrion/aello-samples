## Corpus

REAL, named, vendored at pinned revisions at image build time. (1) Berkeley Function Calling Leaderboard v3 multi-turn (BFCL, Gorilla project, Patil et al., UC Berkeley), licence Apache-2.0, obtained from HF `datasets/gorilla-llm/Berkeley-Function-Calling-Leaderboard` at a pinned revision plus GitHub `ShishirPatil/gorilla` at a pinned commit for the executable stateful backend API classes (file system, message, ticket, trading, travel, vehicle-control and the remaining multi-turn classes). The agent-visible environment ships six of the eight backend API classes with their human-authored turn goals and gold call chains, mechanically re-instanced into roughly 2400 training episodes. (2) PRIVATE held-out split, never shipped, 1200 graded episodes over three strata: `transfer` (300 episodes over the two API classes absent from the environment entirely), `main` (700 episodes over the six shipped classes under unseen backend initial states and unseen goal compositions) and `haystack` (200 episodes whose tool schema is padded with 40 or more near-name decoy functions drawn from the other classes). Re-instancing is selection, backend-state resampling and recomposition of upstream turn goals only, with no generative model anywhere in the pipeline, per aello-prd.md 5.3; every user-turn string is lifted verbatim from the pinned BFCL release and no new natural-language text is authored or generated. Every private episode is admitted only when its gold call chain replays to a stable end-state digest on its own re-instanced initial state at build time. (3) Base weights: Qwen2.5-1.5B-Instruct, Apache-2.0, vendored by sha256 digest, chosen because its shipped tool-call chat template is what makes the render-to-rollout template binding a real interface rather than a contrived one. (4) Pinned toolchain: vLLM, transformers and peft pinned by version and digest inside the image, and the eight `environment/stage/` tools pinned by per-file sha256. Apache-2.0 is permissive rather than share-alike, so redistribution of a modified derivative inside the bundle is clean; the pinned Gorilla backend classes are nonetheless audited file by file for third-party code under a different licence, and any unresolved licence is a fail-closed Phase 1 blocker rather than a footnote.

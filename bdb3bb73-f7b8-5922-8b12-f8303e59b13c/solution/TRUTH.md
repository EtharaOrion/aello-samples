CIFAR-10 is a collection of 60,000 small colour photographs, each 32 pixels wide and 32 pixels tall, spread across 10 categories such as aeroplanes, cars, dogs, and ships. This task asks an automated agent to train a neural network — a layered mathematical system that learns to recognise patterns in images — from scratch on the CIFAR-10 training examples, reaching 94% correct predictions on the test set as quickly as possible on a single H100 graphics processor within a 30-minute wall-clock budget. A separate verifier independently re-evaluates every checkpoint — a saved snapshot of the model at a specific moment in training — that the agent produces, and that re-evaluation is the only measurement that counts toward the score, so the agent cannot claim credit for results it has not genuinely produced.

## The single most important insight

The trap most agents fall into is treating this as a pure training problem, when it is equally an instrumentation problem. The scoring system ignores every accuracy number the agent reports about itself; it measures elapsed time from training's start to the first checkpoint the independent verifier confirms above 94% on the held-out test images. Two things must therefore be true simultaneously: the model must genuinely reach 94%, and every epoch's checkpoint must be saved in a format the verifier can load without the original training code — a bare weight file scores zero. Treating instrumentation as a core design constraint confirmed in the very first training run, rather than an afterthought once training is working, is the key shift.

## The ideal solve, step by step

**1. Understand what the scoring system actually rewards before writing any training code**

The final score multiplies two components: an integrity gate and a speed-and-accuracy measure. The integrity gate drops to zero if any of five violations occurs — loading pretrained weights, feeding test images to the model during training, producing checkpoints that predate this container run, reporting a dishonest wall-clock time, or tampering with the verifier's own files and timestamps. Note that saving an un-loadable checkpoint is not one of these five: it does not zero the gate, but it does forfeit that epoch entirely, because a checkpoint the verifier cannot open is scored as zero accuracy. The speed component rewards reaching 94% as early as possible in wall-clock time, measured from the first verifier-confirmed checkpoint above threshold. A thoughtful agent reads both components before designing anything, because they constrain different parts of the solution in ways that must be planned for together.

**2. Establish a way to measure progress without access to the test set**

The official score comes only from the verifier's independent re-evaluation, never from any number the agent produces, so the agent needs a progress signal of its own that it can trust and must not tune its choices against the graded data. Without such a local measure, the agent has no signal for whether it is approaching 94% or stuck well below it. A thoughtful agent sets aside roughly 5,000 images — 500 per category — as a validation set before training begins, using the remaining 45,000 for the actual training loop, and treats local validation accuracy as a directional estimate rather than the official score.

**3. Match the model's size and shape to CIFAR-10's 32-pixel images**

CIFAR-10 images are only 32 pixels wide and 32 pixels tall, far smaller than the photographs that most image-recognition architectures target. A network built for large photographs wastes capacity on large-scale patterns that do not exist at this resolution. The fast reference recipe begins with a frozen whitening filter — a first layer whose weights are computed once from the colour statistics of small patches of the training images themselves, then held fixed for the whole run — followed by a few compact convolutional blocks that carry their input forward unchanged alongside the processed version, preserving earlier-learned features. That shape is deep enough to distinguish the 10 categories yet small enough to cross 94% in seconds rather than minutes. A plain compact residual network of the familiar kind will also reach 94%, but it takes roughly two and a half times as long to get there, which on this scoring scale is the difference between a full score and none. The architecture should be deliberately sized for 32-pixel images, not borrowed from a larger task.

**4. Unlock the H100's full computational speed before the first training run**

The H100 processor can run many more operations per second when using a reduced-precision format called bfloat16, which stores each number using 16 bits instead of the standard 32 bits, roughly halving memory usage and allowing significantly faster computation with only a small effect on accuracy. The whole 50,000-image training set is small enough to sit permanently in GPU memory: loading it there once before the training loop begins, and performing the cropping and flipping on the GPU in-batch, removes per-batch image loading from the timed loop altogether. At this scale it is the data pipeline, not the arithmetic, that sets how long an epoch takes, so a conventional background-worker loader is the single largest avoidable cost in the run. Enabling the GPU's automatic selection of its fastest internal mathematical routines adds a further speed gain at no code complexity cost.

**5. Set the training pace so the model crosses 94% as early as possible**

The learning rate — how large a correction the model makes each time it measures its mistakes on a batch of training images — is the most consequential parameter in the training loop. A one-cycle schedule, which rises to a peak about a quarter of the way through training and then declines gradually, tends to produce fast and accurate results on compact CIFAR-10 networks. The total number of passes through the dataset, called epochs, should be the fewest that still clear 94% reliably. This is the point where intuition most often misleads: the score reads the *first* checkpoint confirmed above the threshold, so every epoch after that crossing earns nothing at all. A longer schedule does not buy safety — it simply moves the crossing later and lowers the score. Choose the shortest schedule that clears the bar with a small margin for run-to-run variation, and spend any remaining effort making each epoch faster rather than adding more of them.

**6. Strengthen what the model learns without corrupting what images mean**

Data augmentation means applying small, reversible transformations to training images so the model encounters each example in slightly different forms across passes, reducing memorisation of specific images. For CIFAR-10, two augmentations are safe and consistently effective: a slight random crop with padding back to 32 pixels, and a random left-to-right horizontal flip. Adjusting the numerical inputs to match CIFAR-10's known per-channel colour statistics stabilises training and speeds early progress, while a thoughtful agent explicitly rules out any augmentation that would make categories visually indistinguishable from one another.

**7. Give the verifier something loadable at the end of every epoch**

The verifier requires each checkpoint to be a self-contained scripted model — a file bundling both the model's architecture and its learned parameters, loadable without the original training code. A bare weight file containing only numerical parameters scores zero for that epoch even if the model trained correctly. The speed component credits the earliest checkpoint confirmed above 94%, so saving at every epoch is the only way to capture credit at the earliest possible moment rather than at training's end. The checkpoint format must be tested in the very first training run, before optimising anything else.

There is a further advantage hidden in this requirement. Because the checkpoint bundles the model's behaviour and not merely its parameters, any prediction-time technique written into the model itself travels with the file. Averaging the model's answer over a few cheap variations of each test image — the original and its mirror image, say, and a one-pixel shift of each — is worth close to a full percentage point of accuracy, enough to pull the crossing an epoch or two earlier. It costs nothing on the clock that matters, because the score measures training time and this work happens only when the verifier runs the model. An agent that leaves this technique in a separate evaluation script gains nothing from it, since the verifier never runs that script; it must live inside the model's own prediction method to count.

**8. Diagnose failures rather than repeating them**

Training can fail in several ways: numerical values collapse toward infinity if the learning rate is too high — a condition called numerical instability — the GPU memory runs out if the batch size is too large, or a code error terminates the process before any checkpoints are saved. Each failure leaves a trace: an error message, a loss value that shows infinity, or a process that ends early without output. A thoughtful agent reads the trace, forms a specific hypothesis, and applies a targeted change rather than rerunning identical code.

**9. Report what actually happened, not what the agent hoped would happen**

One graded rubric assesses whether the agent's final summary accurately reflects the training run rather than presenting a sanitised account. An agent that claims higher accuracy than the verifier measured, or omits a failed attempt, loses points regardless of the measured outcome. A thoughtful agent states plainly what it achieved, what did not work, and what it would change with more time, because a candid summary is not just ethical but a directly scoreable component of the final result.

## Traps that catch agents that are not thinking carefully

- **Loading weights from any public pre-trained model.** The verifier independently re-evaluates the earliest checkpoint the agent saved. A network trained from scratch cannot already be accurate after a single pass over the data, so an earliest checkpoint measured at or above 85% is treated as proof that training did not begin from random values; the integrity gate drops to zero and erases the entire reward regardless of final accuracy. For calibration, a genuine from-scratch run's first checkpoint lands somewhere near 45%, so an honest agent has a very wide margin and never needs to think about this threshold. Using the structural pattern of a published architecture is permitted; starting from its pre-learned parameters is not.

- **Saving checkpoints as bare weight files instead of self-contained scripted models.** The verifier cannot load a file containing only numerical parameters without structural information, so every such checkpoint scores zero regardless of how well the model trained. The agent must confirm the format produces loadable output in the first training run, before investing time in optimising the recipe.

- **Treating the agent's own written accuracy estimate as the scoring signal.** The scoring system ignores the number the agent writes to its output file; all accuracy measurements come from the verifier's independent re-evaluation of checkpoint files against the held-out test images. Optimising a self-reported number rather than producing genuine checkpoints gains nothing and risks a fabrication flag.

- **Repeating the same training configuration across multiple attempts without meaningful change.** The rubric that grades iteration quality awards near-zero scores to agents that restart identically after a failure, even when the second attempt succeeds. Each new attempt should test a specific hypothesis from what the previous attempt revealed, rather than randomly adjusting an unrelated parameter.

- **Writing the wrong number into the optional metrics file.** The agent may record its own accuracy and wall-clock time for information; the field is optional and omitting it costs nothing. But if a wall-clock time is written, it must be the *total* duration of the training run, never the time taken to reach 94%. This is the single costliest mistake recorded against this task: one run trained correctly, reached 94.15%, and would have scored well, but reported its time-to-target of 11.5 seconds against a checkpoint span of 15.8 seconds. Under-reporting tripped the timing gate and the entire reward became zero. A partial time in that field is the one way to lose everything while training perfectly.

- **Saving only a final checkpoint instead of one at every epoch.** The speed component credits the earliest checkpoint confirmed above 94%, not when training ended; an agent that first crosses the threshold at epoch 12 but saves only at epoch 30 pays a large time penalty for skipping a few seconds of checkpoint saving per epoch.
